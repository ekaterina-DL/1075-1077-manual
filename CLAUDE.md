# Заявки 1075–1077 (Kandinsky. Движения — сбор ссылок)

## Что за проект и для кого
Сайт-мануал для асессоров Data Light, которые собирают ссылки на видео с определённым движением для датасета Kandinsky: повседневность (заявка 1075), танцы (1076), спорт (1077). Работа (включая экзамен) выполняется в личном кабинете на платформе Tagme, доступ к которой выдаёт руководитель группы Data Light.

## Стек
Статический HTML/CSS сайт без фреймворков и сборки, общий `site/assets/style.css`. Хостинг — GitHub, будет настроен позже.

## Структура проекта
- `site/` — сайт-мануал: 6 страниц (`overview.html`, `criteria.html`, `blockiness.html`, `request-1075.html`, `request-1076.html`, `request-1077.html`) + `assets/` (стили, картинки, видео-примеры)
- `sources/` — все исходники от заказчика одной плоской папкой (инструкции, переписка, ОС, видео-примеры) — специально без подпапок, чтобы новые файлы было легко добавлять
- `docs/` — управление проектом: brief, status, tasks, issues, ideas, assets, site-structure, content-extracts

## Текущий статус
Сайт полностью собран (6 страниц) и прошёл полный аудит перед публикацией (2026-09-17): все внутренние ссылки, якоря правой навигации и CSS-классы проверены и рабочие, все файлы в `site/assets/` используются и все использованные файлы существуют. Навигация двухуровневая: слева — страницы сайта, справа — разделы текущей страницы. Заявка 1075 наполнена реальной ОС заказчика; для 1076/1077 «Частые ошибки» пока общие — детальной обратной связи по ним ещё не было. Подробности — в `docs/status.md`.

## Карта файлов проекта
- `site/overview.html` — обзор проекта, экзамен (включая явное предупреждение, что интерфейс экзамена — один видео за раз — отличается от рабочего формата), Tagme, процесс проверки (без персоналий)
- `site/criteria.html` — формат задания, советы по поиску, критерии отбора (Подходит/Не подходит, включая «Рамки»), корнер-кейсы (два, с плашками-статусами), блок про название движения
- `site/blockiness.html` — термин, чек-лист, два разобранных примера (первый — свой mp4, второй — через встроенный YouTube-плеер `<iframe>` по прямой публичной ссылке из ОС), разъяснение HD vs блочность
- `site/request-1075.html`, `request-1076.html`, `request-1077.html` — по каждой заявке: о заявке (с названием в Tagme и пулами), расширенные примеры названий движений (для 1075 — по бытовым темам, для 1076/1077 — по каждому пулу), особенности отбора, разбор примеров на видео, частые ошибки
- `site/assets/` — `style.css`, скриншоты интерфейса (в т.ч. интерфейса экзамена), картинка сравнения блочности, два корнер-кейса, видео-примеры по каждой заявке, логотип Tagme
- `sources/` — официальные инструкции по всем трём заявкам, инструкция для экзамена, переписка с заказчиком (реальные имена асессоров и внутренние метрики ПШЕ), ОС по заявке 1075, вопрос про ГО и блочность — **в `.gitignore`, на GitHub не пушится**, в репозиторий попадает только `site/`
- `docs/content-extracts.md` — вся выжимка из исходников, готовая к переносу на сайт
- `docs/site-structure.md` — исторический план навигации (утверждён 2026-09-16); часть деталей с тех пор менялась на практике — актуальная структура фиксируется здесь, в CLAUDE.md

## Решения, которые уже приняты и не пересматриваются
- Источник видео для сбора — YouTube (внутренне, для куратора). На самом сайте слово «YouTube» текстом не используется — только «видеоисточник» (YouTube заблокирован в РФ с 10.02.2026, сайт публичный для асессоров). Сам плеер YouTube (`<iframe>`) использовать можно — асессоры и так работают с YouTube по роду задачи, ограничение касается только текста страницы, не механики.
- Для новых видео-примеров: если есть настоящая публичная ссылка на источник — встраивать плеером (`<iframe>`, без скачивания); скачивать и класть в `site/assets/` только если публичной ссылки нет (например, ролик закрыт логином в Tagme).
- Формат — статический HTML-сайт, 6 отдельных страниц с общим CSS, без фреймворков.
- Работа асессоров — только через Tagme, доступ выдаёт руководитель группы Data Light.
- На сайте нет персоналий (кто на какой заявке/пуле) — мануал общий и не привязан к конкретным людям.
- Каждое правило живёт ровно в одном месте — дублирование по разным страницам/таблицам сознательно убирается.
- Без тяжёлой системы автопамяти (claude-memory-compiler) — история проекта ведётся вручную через `docs/`.
