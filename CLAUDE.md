# Заявки 1075–1077 (Kandinsky. Движения — сбор ссылок)

## Что за проект и для кого
Сайт-мануал для асессоров Data Light, которые собирают ссылки на видео с определённым движением для датасета Kandinsky: повседневность (заявка 1075), танцы (1076), спорт (1077). Работа (включая экзамен) выполняется в личном кабинете на платформе Tagme, доступ к которой выдаёт руководитель группы Data Light.

## Стек
Статический HTML/CSS сайт без фреймворков и сборки, общий `site/assets/style.css`. Хостинг — GitHub Pages, см. «Публикация» ниже.

## Структура проекта
- `site/` — сайт-мануал: 6 страниц (`overview.html`, `criteria.html`, `blockiness.html`, `request-1075.html`, `request-1076.html`, `request-1077.html`) + `assets/` (стили, картинки, видео-примеры)
- `sources/` — все исходники от заказчика одной плоской папкой (инструкции, переписка, ОС, видео-примеры) — специально без подпапок, чтобы новые файлы было легко добавлять
- `docs/` — управление проектом: brief, status, tasks, issues, ideas, assets, site-structure, content-extracts
- `search-algo/` — рабочий алгоритм предварительного подбора видео-кандидатов (поиск → фильтр → поза → отбор → Excel для проверки асессором): код пайплайна, журнал решений (что сработало/не сработало и почему), критерии отбора, реестр уже выданных подборок — **в `.gitignore`, на GitHub не пушится**, чисто локальный инструмент. При любой новой задаче на подбор ссылок для заявки/пула — сначала смотреть туда (`search-algo/README.md`), не изобретать заново

## Текущий статус
Сайт полностью собран (6 страниц), опубликован и регулярно обновляется вслед за уточнениями заказчика; последние крупные сверки — вебинар с заказчиком 01.10.2026 (минимум 2–3 ссылки, ускоренные видео, вторая попытка экзамена не автоматом), ОС по экзамену 05.10 и снижение проходного балла экзамена до 80%, обновлённые инструкции 1075 от 06.10 и 12.10.2026 (критерии «Рамки» и «Блочность» уточнены; новые правила — мультипликация, «только отражение не считается человеком», роботы/животные), новый шаг «Обучение» перед экзаменом с 07.10.2026 (от 50% — автоматический навык-допуск, в сам экзамен добавляет вручную РГ). Подробности по датам — в `docs/status.md`. Навигация двухуровневая: слева — страницы сайта, справа — разделы текущей страницы; ссылки-якоря, файлы в `site/assets/` и индекс поиска регулярно проверяются скриптом сверки (все использованы, все существуют, 0 расхождений на 13.10.2026). Заявка 1075 наполнена реальной ОС заказчика и дважды обновлённой инструкцией; новые правила из инструкции 1075 от 12.10 внесены на общую страницу `criteria.html` как предположительно общие для всех трёх заявок — официального подтверждения через обновлённые инструкции 1076/1077 пока нет (открытый вопрос, см. `docs/issues.md`). Для 1076/1077 «Частые ошибки» пока общие — заявко-специфичные примеры ждут решения (`docs/tasks.md`, `docs/ideas.md`).

## Карта файлов проекта
- `site/overview.html` — обзор проекта; раздел «Как попасть на проект (обучение и экзамен)» — шаг «Обучение» (с 07.10.2026: от 50% автоматически даёт навык-допуск к экзамену, в сам экзамен всё равно добавляет вручную руководитель группы), экзамен (20 заданий, проходной балл 80%, задания со всех направлений без деления на заявки и пулы; явное предупреждение, что интерфейс экзамена — одно видео за раз — отличается от рабочего формата), блок «Частые ошибки на экзамене» (по ОС 05.10.2026), Tagme, процесс проверки рабочих заданий (без персоналий)
- `site/criteria.html` (в меню — «Правила выполнения заданий») — формат задания (шесть полей: обязательный «Комментарий» — временной диапазон к каждой из 5 ссылок, точно по движению; все ссылки — на разные видео), всплывающее окно при смене пула и бронирование в общем черновике перед Tagme (с перезапуска проектов 23.09.2026), блок «Как не плодить просроченные задания», советы по поиску, критерии отбора (Подходит/Не подходит) в 5 тематических подразделах с вложенной навигацией справа (длительность → идентичность, динамичность, активность, лишние движения → кадр: склейки, блочность (с 07.10 — уточнение «HD не гарантирует качество картинки»), технический артефакт, рамки (с 07.10 смягчено: однотонная — можно, дублирует движение из основного видео — нельзя), перекрытия, вотермарки → человек в кадре: различимость людей (с 13.10 — «только отражение в зеркале не считается, что человек виден»), несколько человек, исполнитель движения (с 13.10, новое — человек/антропоморфный робот/животное, но нельзя смешивать человека и животное в одном задании) → съёмка и обработка: ракурс, скорость (с примером «рывки при ускорении»), зум, коллажи, происхождение (запрет ИИ-генерации и, с 13.10, мультипликации), запрещённый контент), корнер-кейсы (четыре, с плашками-статусами), название движения (пример/антипример, реальные ошибки, отклонение задания за одно только название)
- `site/blockiness.html` — актуальное требование (с 18.09.2026: HD, лучшее видео в поле 1, блочность нестрого — не «откровенно битое»), термин, прежний чек-лист и два разобранных примера (справочно) (оба через встроенный плеер `<iframe>` по прямой публичной ссылке из ОС) и реальные цитаты про путаницу HD и блочности, разъяснение HD vs блочность
- `site/request-1075.html`, `request-1076.html`, `request-1077.html` — по каждой заявке: о заявке (с названием в Tagme и пулами), расширенные примеры названий движений (для 1075 — по бытовым темам, для 1076/1077 — по каждому пулу), особенности отбора, разбор примеров на видео, частые ошибки
- `site/assets/` — `style.css`, `search-index.js` (вручную собранный индекс поиска: страницы/разделы + ключевые слова) и `search.js` (логика строки поиска), скриншоты интерфейса задания и экзамена, картинка сравнения блочности, три корнер-кейса, видео-примеры по каждой заявке, логотип Tagme
- `sources/` — официальные инструкции по всем трём заявкам, инструкция для экзамена, переписка с заказчиком (реальные имена асессоров и внутренние метрики ПШЕ), ОС и выгрузки ошибок валидатора по заявкам (15.09–28.09), вопрос про ГО и блочность, материалы пилота предварительного подбора кандидатов (28.09) — **в `.gitignore`, на GitHub не пушится**, в репозиторий попадает только `site/`
- `docs/content-extracts.md` — исторический документ (16.09.2026, до публикации): выжимка из исходников, уже перенесённая на сайт; актуальный журнал изменений — `docs/status.md`

## Решения, которые уже приняты и не пересматриваются
- Источник видео для сбора — YouTube (внутренне, для куратора). На самом сайте слово «YouTube» текстом не используется — только «видеоисточник» (YouTube заблокирован в РФ с 10.02.2026, сайт публичный для асессоров). Сам плеер YouTube (`<iframe>`) использовать можно — асессоры и так работают с YouTube по роду задачи, ограничение касается только текста страницы, не механики.
- Для новых видео-примеров: если есть настоящая публичная ссылка на источник — встраивать плеером (`<iframe>`, без скачивания); скачивать и класть в `site/assets/` только если публичной ссылки нет (например, ролик закрыт логином в Tagme).
- Формат — статический HTML-сайт, 6 отдельных страниц с общим CSS, без фреймворков.
- Работа асессоров — только через Tagme, доступ выдаёт руководитель группы Data Light.
- На сайте нет персоналий (кто на какой заявке/пуле) — мануал общий и не привязан к конкретным людям.
- Каждое правило живёт ровно в одном месте — дублирование по разным страницам/таблицам сознательно убирается.
- Поиск по сайту — статический (без бэкенда): индекс — вручную поддерживаемый JS-массив (`site/assets/search-index.js`). При добавлении нового раздела/якоря на сайт нужно вручную добавить соответствующую запись в индекс, иначе раздел не найдётся через поиск.
- Значки/иконки в тексте — обычные эмодзи (например, ⚠️), а не встроенные SVG: SVG без стилей отображается огромным.
- Без тяжёлой системы автопамяти (claude-memory-compiler) — история проекта ведётся вручную через `docs/`.
